# Ежедневная автокопия в GitHub в 23:59 (как у Рациона и Lucky Finance)

Дата: 2026-11-21. От: Hermes (по просьбе владельца). Проект: только Тренер.

## Цель
Копия данных Тренера уходит в приватный репозиторий `godoffear/trener-data` **каждый день в 23:59** автоматически, даже если в этот день не было тренировки и приложение не открывали. Нужно, чтобы Hermes и будущий общий дашборд всегда брали свежие данные из одного места.

## Что есть сейчас (проверено)
- Копия делается только из JS: `autoBackup()` в `js/extras.js` — после каждой тренировки и при открытии приложения, если последней копии больше 3 дней. Фонового расписания нет.
- Итог: в `trener-data/trener/history/` пропуски (нет 11, 15, 18 ноября), `latest.json` может быть старым.
- Файлы в репозитории: `trener/latest.json` и `trener/history/trener_ГГГГ-ММ-ДД.json`. Этот формат и пути **не менять**.
- В `app/android/.../` есть `BackupPlugin.java` (запись на телефон), `UpdaterPlugin.java`, `MainActivity.java`. Фонового Worker нет.

## Как сделано у соседей (взять за образец)
- Рацион: `project/apk/android/app/src/main/java/com/godoffear/racion/BackupWorker.java` (+ `RacionNativePlugin`): приложение при работе кладёт снимок данных в SharedPreferences, WorkManager в 23:59 берёт снимок и заливает `latest.json` + `history/racion_ДАТА.json` через GitHub Contents API (GET sha → PUT), повтор до 8 раз при ошибке, статус `ghDay/ghAt/ghErr` для показа в настройках.
- Lucky Finance: `android/.../GhBackupWorker.java`, `schedule(Context, enabled, hour)`: `PeriodicWorkRequest` каждые 24 ч с начальной задержкой до ближайших 23:59 (`hour>=23 → minute 59`), `ExistingPeriodicWorkPolicy.UPDATE`.

## Что сделать
1. Android-часть Тренера: `BackupWorker` (WorkManager, период 24 ч, первый запуск в ближайшие 23:59 по локальному времени телефона). Реализовать по образцу Рациона/Lucky; зависимость `androidx.work` добавить в gradle, если ещё нет.
2. Снимок данных: Тренер хранит данные в IndexedDB, а Worker работает без WebView. Поэтому при каждом сохранении данных (и при сворачивании приложения) JS передаёт в нативный плагин свежий снимок `dbExport()` (JSON), плагин кладёт его в SharedPreferences/файл. Worker в 23:59 берёт этот снимок. Не раздувать частоту записи: достаточно на `finishWorkout`, на сворачивание и на `autoBackup`.
3. Worker заливает в `godoffear/trener-data`: `trener/latest.json` и `trener/history/trener_ДАТА.json` (тот же формат, что `ghPush` в `extras.js`). `latest.json` обновляется **каждый день**, даже если данные не менялись (как у Lucky), чтобы по дате было видно, что копия живая.
4. Токен и репозиторий: использовать те же настройки GitHub, что уже введены в приложении (`ghCfg`). Токен новым агентам не создавать, не хранить в репозитории и не писать в логи. Нативной части токен передаётся из JS при сохранении настроек.
5. Статус в настройках «Бэкап и копии» (`backupInfo()`): добавить строку «Автокопия 23:59: ✓ дата-время / ✗ причина» (по образцу `ghDay/ghAt/ghErr` у Рациона).
6. В `latest.json` добавить поля `exportedAt` и `apkVersion`, только если это не ломает импорт. Обратная совместимость: существующие копии должны по-прежнему загружаться через «Загрузить из файла».
7. Существующее поведение (копия после тренировки и на телефон в «Загрузки/Trener…») не ломать.

## Критерии готовности
- Расписание 23:59 ставится при старте приложения и переживает перезагрузку телефона и закрытие приложения.
- Принудительный запуск Worker (например через `adb shell cmd jobscheduler run` или тестовую кнопку/параметр `force`) создаёт `trener/latest.json` и `trener/history/trener_СЕГОДНЯ.json` в `trener-data`.
- Две ночи подряд (с 21 на 22 и с 22 на 23 ноября) коммиты «Тренер: копия…» в `trener-data` появляются около 23:59 без открытия приложения. Hermes проверит это по истории коммитов.
- Старые копии открываются, статус в настройках показывает результат.
- Запись в `docs/STATUS.md`, `docs/CHANGELOG.md`, при необходимости `docs/DECISIONS.md`. Задачу перенести в `docs/inbox/done/`.
