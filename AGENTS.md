# AGENTS.md — проект «Тренер» (единственный файл правил)

Android-приложение для силовых тренировок: обычные HTML/CSS/JS + Capacitor 8, `appId com.godoffear.trener`. Репозиторий: github.com/godoffear/trener (**публичный** — личных данных, токенов, ключей в файлы не писать). Работай только с этим проектом.

## 0. Кто может работать и какие права (решение владельца, 2026-11-20)
Любой из помощников — **Codex (ChatGPT)**, Antigravity, Claude Code — имеет **полные права** на проект: править код, программу и дизайн, собирать APK, **подписывать его** ключом владельца с этого Mac, коммитить, пушить и **выпускать релизы на GitHub**, чтобы обновление пришло на телефон. Ограничения «Codex — только дизайн» **отменены**. Возможно, Claude Code у владельца пропадёт, и тогда проект ведёт Codex целиком.
- **Подпись:** стандартный ключ `~/.android/debug.keystore` на ноутбуке владельца. `tools/build.sh` подписывает им сам (Gradle `assembleDebug`), отдельных паролей вводить не нужно. Ключ не копировать, не менять, не коммитить, не пересылать; собирать только на этом Mac, иначе телефон не примет обновление поверх.
- **GitHub:** на этом Mac уже выполнен вход `gh` как `godoffear` (`gh auth status`). Если ты работаешь на этом Mac, используй `gh` и `git push`. Если не получается (нет входа, истёк токен, ошибка 401/403) — попроси у владельца новый токен: GitHub → Settings → Developer settings → Fine-grained tokens → репозиторий `trener`, Contents: Read and write, срок 90 дней; передаёт он тебе в чат. В файлы токен не записывать. После замены напомни владельцу заменить токен и у остальных помощников и отозвать старый.
- **Подтверждение владельца** по-прежнему нужно только перед выпуском версии (раздел 6), если в его сообщении или задаче в `docs/inbox/` не сказано «выпускай» / «опубликуй N».

## 1. Начало каждой сессии
1. `git pull`.
2. Прочитай `AGENTS.md`, `docs/STATUS.md`, папку `docs/inbox/` (задачи владельца; их присылает его ассистент Hermes).
3. Бери задачи из `docs/inbox/` по порядку; сделанную задачу переноси в `docs/inbox/done/`.

## 2. Правила работы
- Лишних вопросов не задавай: решай сам по здравому смыслу и описывай решение в `docs/DECISIONS.md`.
- **Подтверждение владельца нужно только перед выпуском версии** (релиз на GitHub). Всё остальное делай без вопросов.
- После каждой правки: обновить `docs/STATUS.md` (и `docs/CHANGELOG.md`, если меняется поведение приложения), затем `git commit` и `git push` сразу.
- Владелец — новичок, пишет по-русски. Отвечай по-русски, коротко, простыми словами. Если что-то не проверено на реальном телефоне — скажи честно.
- Никаких токенов и паролей в файлах, коммитах, логах. Если GitHub просит подтверждение доступа или 2FA — остановись и верни управление владельцу.
- Не использовать `rm -rf` с масками. Ничего не удалять с диска: старое — в `_archive/` (она в `.gitignore`).

## 3. Структура
- Корень = актуальная версия сайта: `index.html`, `privacypolicy.html`, `css/`, `js/`, `fonts/`, `icons/`, `img/`.
- `app/` — Android-проект Capacitor (`app/www` и сборки в git не попадают).
- `tools/build.sh` — сборка APK. `tools/` — прочие скрипты.
- `docs/`: `STATUS.md` (текущее состояние), `inbox/` (задачи), `DECISIONS.md`, `CHANGELOG.md`, `docs/private/` и `_archive/` — только локально.
- `sw.js`, `manifest.webmanifest`, `dev/` — остатки старого сайта godoffear.github.io/trener (PWA 0.20). Приложению они не нужны (оно проверяет обновления через `api.github.com/repos/godoffear/trener/releases/latest`), но не удалять без решения владельца.
- Версия одна: история версий = история коммитов. Папки `versions/vN` больше нет (старые лежат в `_archive/versions`, только локально).

## 4. Устройство кода (`js/`)
- `exercises.js` — справочник `EX`, списки реальных весов зала `STACKS` (`cross`, `db`, `fixed`).
- `program.js` — программа по дням, `restOf(ex)`, `PROGRAM_V`.
- `progression.js` — двойная прогрессия по плитам `STACKS` (скачок >20 % → +2 повтора сверх верха; >40 % → +4).
- `app.js` — интерфейс, `APP_VERSION`, `stackOf`, `defMode`. `workout.js` — тренировка, замены, итог. `db.js` — IndexedDB (`D`, `dbPut`, `saveKV`), одноразовые миграции в `dbLoad` по `PROGRAM_V` и флагам `settings.fixNN`. `hlog.js` — журнал Health Connect. `extras.js`, `sounds.js`, `muscles.js`, `achievements.js` — остальное.
- При смене программы: поднять `PROGRAM_V`, добавить миграцию в `db.js`, чтобы история тренировок на телефоне не потерялась.
- Прогрессия и отдых: 120 с тяжёлые базовые, 75 с изоляция, 60 с пресс; лимит дня 70 мин — только предупреждение.
- Реальные веса зала: кроссовер 7, 9, 14, 18, 23, 30, 36, 43, 50, 57, 64, 70, 77, 84, 91; бабочка и ноги 5–80 шаг 5; рычажные тренажёры на блинах шаг 5 (жим на сторону); гантели 5–40 (список в `STACKS.db`); готовые штанги 10, 15, 20, 25, 30.
- Программа (5 силовых дней: Пн грудь/трицепс/пресс, Вт спина/бицепс, Чт плечи и руки, Пт верх, Сб ноги; Ср бег) — подробности в `js/program.js`.

## 5. Сборка и проверка
```bash
tools/build.sh      # → APK/Trener-v<APP_VERSION>.apk
```
Нужны JDK 21 (`/opt/homebrew/opt/openjdk@21`), Android SDK (`~/Library/Android/sdk`), Node (`npx cap`). Подпись — стандартный `~/.android/debug.keystore` на этом Mac (не менять и не копировать: иначе телефон не поставит обновление поверх).
Перед выпуском: синтаксис (`node --check js/*.js`), прогон в браузере (`python3 -m http.server`, ширина 375×812), проверка миграции на старой программе, `unzip -p APK/Trener-vN.apk assets/public/js/app.js | grep APP_VERSION`.

## 6. Выпуск версии (только после «да» владельца)
1. Подними `APP_VERSION` в `js/app.js` (например `'37.0'`), обнови `docs/CHANGELOG.md` и `docs/STATUS.md`, закоммить, запушь.
2. `tools/build.sh`.
3. Релиз — обычный (не draft и не pre-release), тег `vN.0` строго больше версии, установленной на телефоне, название «Тренер N.0», APK приложен:
   `gh release create vN.0 APK/Trener-vN.apk --repo godoffear/trener --title "Тренер N.0" --notes "..."`
   (`gh` уже авторизован как godoffear; токены в файлы не писать.)
4. Проверка: `https://api.github.com/repos/godoffear/trener/releases/latest` вернул нужный `tag_name` и APK ненулевого размера. Скажи владельцу: «обнови через Ещё → Проверить обновление».
- Существующие релизы не трогать и не удалять.
- Сайт godoffear.github.io/trener собирается из ветки `main` (корень): push в `main` его обновляет. Это допустимо, но не ломать `index.html`.

## 7. Тексты и дизайн
- Все тексты в приложении по-русски. Тёмная тема по умолчанию, цвета только через CSS-переменные (`--acc`), кнопки не меньше 44 px, главное действие внизу, поля 16 px, меньше визуального шума.
- Не ломать нижний лист `#sheet`, нижнюю панель и отступ под статус-бар (`MainActivity`).
